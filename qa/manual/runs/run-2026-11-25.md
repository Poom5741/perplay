## Defects (report only — no product code touched)

### D1 · Receipt block never renders on projection screen — HIGH (blocks demo's core proof)
- Symptom: `#receipt` on `#/screen/:id` permanently empty; on-chain tx link, anchor warning + retry link, and end-to-end seconds never shown; the 1.5 s polling (`poc/public/app.js:116-120`) silently fails every tick.
- Root cause: `renderReceipt` (`poc/public/app.js:123-130`) calls `t(p.timings.requested)` at `app.js:125`, but `t` is defined only inside `pageScreen` (`poc/public/app.js:107`). Every call throws `ReferenceError: t is not defined` (captured live in the page during the run).
- Repro: any request → confirm → open `#/screen/:id`, inspect console.

### D2 · Audio-scan verifies a play with a DIFFERENT song's fingerprint — HIGH (licensing-integrity)
- Symptom: S003 play + upload of S001.wav → status `verified`, `matchedSong: "S001"`.
- Root cause: `poc/server.mjs:192-197` matches the uploaded hash against any catalog fingerprint and marks the play verified without comparing `match[0]` to `play.songId`.
- Impact: per-song licensing proof is not tied to the song actually paid for; a venue could verify a play using any catalog audio.

### D3 · Server stopped listening after first audio-scan upload — MEDIUM (one-off, log lost)
- Symptom: after uploading S002.wav (~08:21), the process stayed alive but port 3000 refused connections; required restart.
- Note: log output went to a killed background shell, so the exact exception is unknown. The second scan upload on a fresh server did NOT reproduce. Data persisted correctly up to the crash (`poc/data/plays.json` written 08:21). Recreate with: acr play → confirm → upload, watch port.

### D4 (ops, not product) · Concurrent duplicate servers clobber `poc/data/plays.json`
- During the run two `node server.mjs` instances coexisted briefly; each holds an in-memory map and last writer wins, so plays created under instance A disappeared after instance B saved. Only ever run one instance; `data/` wipes are also implied by e2e (`tests/qa-baseline.md`).
