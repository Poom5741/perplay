# DEMO SCRIPT — 5 นาที (อ่านเป็นลำดับ · ทดสอบกับพ่อ = proxy Grammy)

> เปิด **https://playright.169-58-137-159.sslip.io** จากมือถือ (หรือให้พ่อเปิดเอง — นั่นคือจุดขาย)
> ถ้าจะเริ่ม ledger สะอาด: `rm -rf data && sudo systemctl restart playright-poc`

## นาทีที่ 0–1 · โจทย์ (พูดก่อนแตะจอ)

> "ผับทุกที่เปิดเพลงค่ายต้องจ่ายค่าลิขสิทธิ์รายปี แต่ค่ายไม่รู้ว่าเพลงไหนถูกเปิดกี่ครั้ง แฟนศิลปินได้อะไรกลับมา ผมทำระบบให้จ่าย **ต่อเพลง** 20–50 บาท ค่ายได้ 70% ทันที มีหลักฐานบน blockchain ทุกครั้ง"

## นาทีที่ 1–2 · ลูกค้าขอเพลง (มือถือ)

1. เปิด URL → หน้า catalog 100 เพลง (บอกชัด: mock data ชื่อสมมุติ — ใช้แค่ทดสอบ)
2. แตะเพลง → **QR PromptPay ขึ้นพร้อมยอด** — "QR นี้เป็น payload PromptPay จริง มาตรฐานธนาคาร แต่ PoC ยัง simulate การรับเงิน"
3. กด **ยืนยันชำระแล้ว**

## นาทีที่ 2–3 · จอฉาย + หลักฐานบน chain

4. จอเปลี่ยนเป็น **"กำลังเล่น: … — ได้รับอนุญาต ✅"** — "นี่คือจอหลังวง ร้านโชว์ได้เลยว่าเพลง licensed"
5. ชี้ลิงก์ **receipt on-chain** → กด → เปิด basescan ได้ tx จริง (input data คือรายละเอียด play) — "ทุก play มีหลักฐานถาวร แก้ย้อนหลังไม่ได้"
6. สังเกตบรรทัด **end-to-end: X.Xs** — "ทั้ง flow จากขอเพลงถึงหลักฐานบน chain ใช้ 1–3 วินาที เป้าคือ 30"

## นาทีที่ 3–4 · Split + สองโหมด verify

7. ไป **Dashboard split** — "จ่าย 30 บาท → ค่าย 21 / ร้าน 3 / แพลตฟอร์ม 6 · สะสมจริงต่อค่าย ต่อร้าน"
8. อธิบาย 2 โหมด: **วงสด** = วงลงเซ็ตลิสต์ล่วงหน้า (เชื่อถือได้กว่า fingerprint เสียงสดที่งานวิจัยแม่น ~87%) · **DJ/เครื่องเสียง** = จับ fingerprint จาก line-in จริง (production ใช้ ACRCloud ~17 สตางค์/จับ, มี free trial 14 วัน)

## นาทีที่ 4–5 · ปิดด้วยคำถามหาพ่อ (เป้า LOI)

- "ถ้าเป็น Grammy สิ่งไหนต้องเห็นก่อนถึงจะลอง pilot 1 ผับ?"
- "ระบบ royalty ที่ Grammy เคยจะทำ ตอนนี้ตายเพราะอะไร — ตัวไหนของเราแก้โจทย์นั้น?"
- "ขออีเมลทีม/ผู้เกี่ยวข้องที่รับผิดชอบเรื่อง licensing เพื่อส่ง PoC นี้ + ตัวเลข pilot เป็น LOI"

**กติกา:** ถ้าถามเรื่องรับเงินจริง → ตอบ "phase 2 — ใช้โครงสร้าง WORPT ที่ผ่าน BOT sandbox แล้ว แปลงเงินตอนจ่าย ร้านไม่เห็น crypto" · ถ้าถาม scale → "50 ผับ = 0.25 ล้านบาท/เดือน margin 96%/play ตาม unit economics ที่คำนวณไว้"
